## Agreed plan
Public design saved in docs/msm6295_design.md, explicitly marked unimplemented.
Native immutable commands/ROM/State/Segments -> inferred accepted/ignored source
requests and four-voice playback -> cached decoded/resampled/re-encoded assets
-> existing shared PCM8/96slot/typedMDX/EX-PDX backend. No song mix or per-gate
waveform capture. Asset identity uses content, dependency/rate/reset profile,
not sample number, volume or early-stop duration. Source gain maps separately
throughPCM8 with explicit quantization losses. Do not copy6295 compressed bytes
into6258 targets or share a decoder merely because names are similar.

Initial fixed-clock/single-chip/basic-bank OPM+6295 route; raw extension writes
retained and active unsupported dependencies diagnosed. Native malformed/ignored
requests vs missing ROM remain distinct. Preserve command latch, busy state,
voice cursor and native ordering across song loops. Start with explicit finite
baseline; separately validate target loop continuation without invented attacks.

Independent architect review agreed with these boundaries and emphasized:
- pin/hash runtime core plus OKI ADPCM dependency before implementation;
- exact native-frame completion vs subsequent same-tick start ordering;
- busy/invalid requests still consume the two-byte command latch;
- ignore invalid ranges only where reference confirms, not unknown ROM;
- source silent attenuation still advances/occupies voice;
- no implication of playback-memory fit from8voice/96slot/file-budget fit.
Minimum authored oracle cases and staged implementation order are in the public
design. User continues broad local_only regression/listening after implementation.
